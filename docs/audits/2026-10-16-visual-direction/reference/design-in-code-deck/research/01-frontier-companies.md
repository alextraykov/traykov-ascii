# Designers delivering coded prototypes: frontier / AI-native companies

Research date: 2026-10-15. Method: web search + page fetches. Every URL below was either fetched or appeared in search results this session.

**Reliability note (read first):** page fetches were summarised by a small model, so details (numbers, names of internal tools, "who merges") are only as good as that summary. Anything I could not see in the primary text is tagged `[unverified]`. Paywalled podcast pages (Lenny's, Dive Club, Product School) were NOT read in full. Where I only have an episode blurb, I say so. Quotes marked "(summary)" came through a summariser and should be re-checked against the source before you reuse them publicly.

## TL;DR

- **Strongest, best-documented practices:** Notion (prototype playground repo), Stripe (Protodash), Anthropic (every designer pushes a PR at onboarding), Jane Street (prototype-as-feature-submission), OpenAI Codex (designers + content designers submit PRs).
- **Almost every company that does this has the same foundation:** design system exposed in code/MCP + agent rules file + a place to put prototypes that is NOT production.
- **Git is handled in 3 ways:** (a) designers learn branches/PRs (Anthropic, Ramp, OpenAI), (b) git is abstracted behind a command/skill (Notion `/deploy`, Stripe "you don't need to know the commands"), (c) prototype PRs are explicitly disposable and engineers re-implement (Jane Street).
- **Airtable, Shopify, GitHub, Lovable:** thin public evidence. Airtable = job-description language only. Shopify = nothing designer-specific found. GitHub = nothing designer-specific found (only a Head of Design talk abstract and tooling).
- **Skeptics worth quoting:** Linear (Karri Saarinen: code forces early commitment), Stripe (Katie Dill: "Fast is not finished"), Anthropic (Joel Lewenstein: risk of solo loops), Jane Street (passive reviewers).

## Anthropic

### A1. Designer Fund: "When code is no longer the constraint: Inside Anthropic's design team"
- **Who:** Joel Lewenstein (leads product design), Nate Parrott, Meaghan Choi, Kyle Turman (designers), Matt Gallivan (UX researcher). Titles as given in the summary; Lewenstein also described as "Anthropic's head of design" in another result.
- **Date:** 2026-10-06 (very recent)
- **URL:** https://designerfund.com/blog/ai-design-anthropic
- **Where prototypes live:** interactive HTML previews generated by Claude; local front-end environment; production for shipped work. Staff have built ~30 custom internal IDEs.
- **Git:** every designer pushes a pull request during onboarding. Designers keep branches and submit PRs as standard practice. Who merges: not stated `[unverified]`. Hiring signal: baseline GitHub/branch/PR comfort.
- **Foundations:** Choi built reusable skills (`/fresh`, `/preview`, `/prototype`); `/prototype` generates five interactive HTML variations and Claude recommends one. Parrott fed the full Anthropic design system (fonts, colors, components, guidelines) into Claude's HTML environment; that workflow became Claude Design.
- **Process changes:** crit frequency up from 2x to up to 4x weekly in small pods; standups stretched from 30 to 90 minutes for pre-implementation alignment.
- **Caveats:** velocity gap (engineering ~10x faster, design ~3-5x). Risk of "disappearing into a solo loop" (Lewenstein). Abundance of options makes converging harder. Workflows need "molting" every few months as models change.
- **Quote:** "Code is basically one more tool in the tool belt." (Lewenstein, summary)

### A5. Claude Design (Anthropic Labs product)
- **Launch:** 2026-04-17, research preview, Pro/Max/Team/Enterprise. URL: https://www.anthropic.com/news/claude-design-anthropic-labs
- **Mechanics:** reads codebase + design files during onboarding to build a design system; can start from a codebase; packages a **handoff bundle** passed to Claude Code in one instruction; exports to Canva/PDF/PPTX/HTML; org-scoped sharing; Enterprise off by default.

- **June 2026 update:** sync design systems into Claude Code, edit design projects from terminal, output checked against design system. Source: https://www.leadwithai.co/article/claude-design-gives-teams-more-control-over-ai-built-prototypes (2026-06-23). Caveat in source: success depends on "the right assets, rules, and review habits".
- **Nate Parrott (Product Designer) case study:** solo designer on Claude Code for VS Code with two engineers; engineering velocity outran design capacity (Sep-Nov 2025). Prototypes live as shareable HTML artifacts; hand to Claude Code which "continues from your existing work". URL: https://claude.com/blog/how-the-product-designer-who-built-claude-design-uses-it-to-explore-ideas-before-building-them

## Notion (deep dive)

### N1. Brian Lovin (designer, Notion AI): How I AI, "I haven't written a single line of front-end code in 3 months"
- **Date:** 2026-02-23. URLs: https://www.lennysnewsletter.com/p/i-havent-written-a-single-line-of ; https://chatprd.ai/how-i-ai/how-notion-designs-with-ai-brian-lovins-prototype-playground-and-claude-code-workflows ; https://stationlm.com/analysis/6228dbd8-a58b-4d99-938a-87d8ff2e0991 (third-party summary)
- **Where prototypes live:** "Prototype Playground", a single **Next.js app in one GitHub repo, deployed on Vercel** as a shared feed. Each designer/PM/engineer gets a **namespaced directory** under `app/` so nobody collides. File-based, no backend. External prototypes (Figma, v0, Lovable) can be linked into the same index.
- **Git:** `/deploy` slash command: checks `gh` auth, creates a descriptive branch if on main, commits, pushes, opens PR, opens it in the browser, then **watches CI every 30-60s and tries to fix lint/type failures** until green. Team commonly merges after CI; code review is optional **because it is a prototype repo, not production**. GitHub Desktop also mentioned.
- **Foundations:** shared Notion-branded components, color/type tokens, templates (e.g. a Notion-style sidebar); global `claude.md` (Bun, Tailwind, structure, conventions) plus a per-user `claude.local.md` with guardrails like "don't modify others' prototypes"; a `/findicon` skill backed by a script searching 5,000+ icon files with synonyms (to stop the model hallucinating icon names); plan mode; Figma-to-code with self-correction loops.
- **Principle:** teach the AI to answer its own questions. "Anytime the AI asks you to do something, teach it to do that itself" (summary).
- **Adoption caveat:** only ~5-10 designers use it regularly; others stay in Figma, own repos, v0, Lovable. Most useful for people with a technical background; `/deploy` was built to reduce git/CLI intimidation.
- **Caveats:** Figma-to-code first pass ~60-80% right; MCP tools "context inefficient" and flaky; designing AI products requires real models in the loop because you can't prototype conversational behaviour in Figma. (all via summaries)
- **Prototype playground vs production:** explicitly separate. Not a designers-push-to-prod story.

### N2. Brian Lovin AMA answer

## Stripe

### S1. Owen Williams (Design Manager): Protodash, How I AI "Demos not memos"
- **Date:** 2026-05-04 (Lenny page) / 2026-05-12 (Roger Wong write-up). URLs: https://www.lennysnewsletter.com/p/this-week-on-how-i-ai-the-internal ; https://rogerwong.me/2026/05/stripe-protodash-ai-prototyping ; https://www.casestudy.club/issues/002/ ; https://departmentofproduct.substack.com/p/deep-how-stripes-design-manager-built
- **What it is:** started as a bundle of Cursor rules + React components, grew into a browser-based prototyping studio running in dev boxes with a design review mode, variants, AI iteration.
- **Where prototypes live:** dev boxes / localhost, disposable by intent; rendered with Stripe's real production components and mock data. Roger Wong's summary says prototypes function as **pull requests** that engineers treat as source of truth "this has never happened ever in my career". Designer Fund says a Radar project used Protodash output as "the primary source of truth for the engineering team" (see S2). Merge process `[unverified]`.
- **Git:** abstracted. "You don't even need to know the commands." (summary). Biggest mindset shift: not fearing the terminal.
- **Foundations:** Sail design system exposed via an **MCP server**; if a Figma link is pasted the tool consults the Sail MCP before writing code; extensive Cursor rules; router and chrome scaffold; constrained generation to stop invented components. Generic v0 gave "blurple slop" because it didn't know Sail.
- **Adoption surprise:** PMs adopted as fast as designers (paste PRD, get a flow before design engages). Williams worried: "PMs designing... what's going to happen?"
- **Caveats:** ~80% fidelity; can't tell prototype from production mid-meeting, wants a "low-fidelity mode"; framing (what to prototype) stays human. Design reviews moved from memos to live prototypes.
- **Quotes (summary):** "Demos not memos." "It's so convincing that I'm like, is this the real product..."

### S2. Designer Fund: "How Stripe creates room for good ideas to spread"
- **Date:** 2026-09-15. Katie Dill (Head of Design), Owen Williams, product designers. URL: https://designerfund.com/blog/ai-design-stripe
- Quarterly **"AI-cation" days** for designers to prototype and build microtools; demos, brown bags, founder fireside chats.
- Caveat: "Fast is not finished." Test: "Would I be proud if it took two weeks to get here?"

## Patterns across companies

1. **Three delivery shapes, not one.**
   - *Prototype as PR* (Anthropic, OpenAI, Jane Street, Stripe per Wong): designer opens a PR that is a proposal; engineers review or re-implement.
   - *Prototype in a separate shared sandbox* (Notion playground, Ramp sandbox, Stripe Protodash in dev boxes): deployed preview feed, not production.
   - *Prototype as shareable artifact* (Anthropic HTML artifacts / Claude Design, v0 previews): link, not repo.
2. **The sandbox/playground is the dominant pattern for non-engineer designers.** Namespaced folders per person, one repo, one deployed feed, CI that fixes itself. Production PRs from designers are the exception and appear mostly at Anthropic, OpenAI, Ramp (for polish) and Jane Street (as proposals).
3. **Git is hidden or taught, never ignored.** Anthropic teaches (PR at onboarding). Notion and Stripe abstract via a command/skill. Ramp engineers taught first PRs. Jane Street uses an internal feature process engineers already own.
4. **The foundation list is remarkably consistent:**
   - Design system as code that agents can read (Sail via MCP; Notion shared components; shadcn registry; Figma MCP with 1:1 token mapping).
   - Agent rules files (global plus local `claude.md`, Cursor rules) with safety guardrails such as "don't touch others' prototypes".
   - Reusable skills/commands for repetitive steps (`/deploy`, `/findicon`, `/prototype`, `/fresh`).
   - A place to put prototypes that is not production.
   - Training time (Stripe AI-cation days, Lovable "we'll train you", Ramp engineers pairing).
   - Well-named components and tokens. OpenAI and Vercel both say naming/architecture directly affects agent accuracy.
5. **Generic tools fail without your design system.** Stripe ("blurple slop"), Anthropic/Jenny Wen (Claude misses DS components), Vercel (wrapper-heavy libraries degrade accuracy).
6. **Figma is not dead, it moved.** Ramp: LLM, then code, then customers, then Figma "for systems and polish". Jenny Wen: Figma for divergence. Linear: Figma exploration then agent prototypes then back to Figma. Anthropic Parrott/Choi: HTML first.
7. **Adoption is partial.** Notion: ~5-10 regular users. Industry: 50% of designers shipped AI code, but 68% early-stage vs 33% public companies. PMs are adopting the same tools faster than expected (Stripe, OpenAI), which raises a role-boundary question.
8. **Caveats that recur:** early commitment / reduced exploration (Linear, Designer Fund report, Jane Street); prototypes look finished so reviewers can't tell fake from real (Stripe); solo-loop risk and weaker live collaboration (Anthropic); fidelity ceilings ~60-80% (Notion, Stripe); cost and rate limits (Claire Vo, Claude Design); front-end ownership and review accountability (Tecla essay); environment setup friction (Cursor panel).
9. **Process knock-ons:** more crits, longer alignment standups (Anthropic); "demos not memos" reviews (Stripe); prototypes replace PRDs (OpenAI).
10. **Evidence quality varies.** Best primary sources: Jane Street blog, Anthropic launch post and Designer Fund interviews, Vercel/Figma official blogs, job descriptions (Ramp, Airtable, Lovable). Weakest: Airtable, Shopify, GitHub, Figma-internal.
