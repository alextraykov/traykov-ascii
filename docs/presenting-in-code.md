# Presentations in code

`/labs/presenting-in-code/` is a continuous teaching website built from the owner's existing interactive tutorial primitives. The original presentation remains a secondary reference and downloadable artifact.

## Website motion brief

The website is an explanation surface, with polish and restraint. Three shared reveal/scan entrances introduce the plan, camera and comparison; the above-fold demo is immediately visible. They use the portfolio's existing timing, easing and no-JavaScript gate.

The layer sequence is the only sticky passage, bounded to 2.3 viewport heights on wide screens. Crossing a scroll boundary selects one of the original flat/copies/tilt/lift/lines states; each threshold triggers the original transform transition using the portfolio’s 340 ms duration and 60 ms stagger tokens. This is a triggered transition, not a continuously eased scroll transform. Scrolling back rewinds. Manual stage selection, pinned surfaces and display options suspend scroll selection until the visitor explicitly resumes it. Scrolling is never intercepted. Narrow screens use ordinary flow and manual controls.

The existing camera, FLIP and layer primitives retain their source transform/opacity implementations for deliberate manual demonstrations, with the website spatial duration set to 340 ms and shorter portfolio fade tokens. Rapid camera input retargets the original transform. A design toggle that interrupts pending or animated source work uses the original cut path to settle the newest state; this prevents a deferred React update from restoring an older Before/After state. Reduced and paused states use their immediate cut mechanism. Primary copy and controls remain at webpage scale. In-screen toolbars occupy their own normal-size row, outside the fitted source drawing. A normal-size inspection label and Back to whole screen control stay inside the artwork so narrow layouts have an immediate exit. Reduced or paused motion disables scroll selection, removes the sticky passage, and makes every manual state immediate. Frame sampling starts only on request and stops on request, when offscreen, or when the page becomes hidden. Native skill disclosures, meaningful deliverable stills, and downloads remain available without JavaScript.

- The supplied compiled runtime gains a small named-export boundary. The registry for the secondary deck is limited to `#making-of`; dormant fictional-product modules remain in the bundle without an exposed route. No confidential product artifact is copied.
- `web/runtime-api.js` mounts only those primitives in Shadow DOM. A local copy of the original CSS is read with `:root` mapped to `:host`; root/body/reset rules cannot style the portfolio. The original screen class roots are renamed to `deck-screen` / `deck-screen-dark` in JS and CSS together, following the recovered tutorial build configuration.
- The visual artboard retains its source coordinates; readable labels, buttons and explanatory copy are normal responsive page elements. Layer scale responds to its container. The live screen is directly interactive: an on-screen action opens the flat screen into the stack; pointer hover and keyboard focus identify measured surfaces without moving them. Click, tap, Enter or Space pins the original plane lift/dim and bounded component close-up. Escape, empty space and one contextual Back to whole screen control clear it. Five compact stage buttons explain the sequence and remain a single strip on mobile; the redundant level buttons, component dropdown and second reset are removed. Theme, tags and blueprint share a native Display options disclosure whose contents overlay without changing sticky geometry. The adapter passes the source layer string to LayerStage and uses its original projectTargets interpolation, reading rendered corner anchors during transform transitions and resize so hit polygons remain aligned. The web adapter composes the original orthographic stack and plane transforms into equivalent 2D plane matrices in both browsers: WebKit otherwise reports raised geometry while painting flattened faces. Original inline transform targets, components, timing, stagger, lift and dimming remain in place; filtered mutation and resize observers update composed targets, and CSS handles interpolation. Transition measurements stop at rest, offscreen and when hidden. Fake interface controls stay inert inside the visual layer; the measured surface buttons are accessible outside that inert subtree. The anchor note occupies its own footer row; the leader terminates at its measured top edge without covering a target.
- The layer sequence uses the existing stage primitives with the portfolio's 340 ms transform duration and 60 ms stagger tokens. The original standalone presentation retains its own timing. The website follows the shared motion lifecycle, offers manual control at every stage, and stops following scroll after deliberate selection until explicitly resumed. Passive pointing never takes scroll ownership. The Follow scrolling control reserves its row even while disabled, and transient identification stays inside the artwork.
- Frame readings use the original sampling and overlapping-text checks. Sampling is opt-in and stops offscreen or when hidden; results are measurements, not performance certification.
- Five static deliverable views are captured from these working primitives for no-JavaScript use. They are fallbacks; the normal page runs the real DOM demonstrations. Every skill and download remains available without JavaScript.
- Alexander's authored tutorial, skills, posts and website adapter use the owner-authorized MIT license. Third-party runtime notices and the Geist OFL license remain separate. No dependency is added.
- The deck-plus-skills ZIP is a compiled runnable distribution with a loopback-only launcher. It is not represented as the missing editable React project. Its 13-slide / 45-state deck remains available as a secondary reference.

## Original technique → direct website interaction

| Website demonstration | Original material retained | What the visitor can actually do |
| --- | --- | --- |
| Hero / before-and-after | `BlueprintScreen`, `Camera`, source `beforeFix` / `proposedFix`, reversible FLIP | Click Input, Panel or Cards to switch the whole screen state; the in-screen switch does the same. The changed geometry is the source component, not a second picture. |
| Camera | Original named selectors and `Camera` world transform | Click a component to frame its complete live bounds. The adapter derives source-coordinate rectangles from the actual layout, rather than retaining the deck's intentionally cropped Panel close-up. Whole screen and Escape return; the displayed scale is read from the rendered matrix. |
| Live anchors | `measureAnchor`, original input-emphasis `anchorFix` / `proposedFix` | Select Input, Panel or Cards on the whole screen. The ring and footer leader track the selected rendered bounds during source changes and resize. The source Before/After change alters Input emphasis and height; it does not pretend to independently edit Panel or Cards. Clear note and Escape remove the annotation. |
| Layers / tagging / pointing / blueprint | `LayerStage`, `BlueprintScreen`, plane geometry and `projectTargets` | Open the original screen, select actual planes/components, inspect their lift/dim/zoom, then return. Existing tag and blueprint switches remain. |
| Frame check | Original `useFrameProbe` and text-overlap sampling | Start/stop on the comparison screen, switch its actual state, and read live intervals/overlaps on screen. The detailed native panel also shows long-task support. Both controls share one visible/hidden sampling lifecycle. |
| Plan / setup | Supplied planning and host concepts | Explicitly labeled example deliverables and a working deep link to the source deck, not inert controls masquerading as applications. |

Camera and comparison drawings remain inert because the source is a blueprint illustration. Native measured targets outside that inert subtree provide the advertised actions, with Tab/Enter/Space and touch parity. Passive hover only highlights; it never moves the camera or component. A stationary pointer cannot retrigger hover during a flight. Bounded animation-frame measurement follows original CSS/WAAPI animation lifecycles and stops at rest, offscreen or hidden. Reduced/paused updates use the original cut mechanism to settle active source animations and render the same destination immediately. The standalone source deck and ten skill files are unchanged by these direct-interaction additions.
